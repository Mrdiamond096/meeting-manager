# ADR-016: มอบหมายผู้สัมภาษณ์หลายคนต่อนัด

**Status:** Accepted (ผู้ใช้ตัดสิน 18 พ.ย. 2026) · แทนสิทธิ์ INTERVIEWER แบบอ่านอย่างเดียวใน ADR-015

## Context

นัดที่ Interviewer จัดการได้หมายถึงนัดที่ Recruiter/Admin มอบหมายให้ ไม่ใช่นัดที่ Interviewer สร้างเอง
ผู้ใช้เลือกให้หนึ่งนัดมีผู้สัมภาษณ์หลายคน แก้ไข/ยกเลิกได้แต่ลบไม่ได้ และยังเพิ่ม feedback ในนัดของคนอื่นได้
`created_by` ต้องคงความหมายผู้สร้างเดิม จึงใช้แทนผู้รับมอบหมายไม่ได้

## Decision

| การกระทำ | ADMIN | RECRUITER | INTERVIEWER |
|---|---|---|---|
| ดูนัด ปฏิทิน ผู้สมัคร และเพิ่ม feedback | ทุกนัด | ทุกนัด | ทุกนัด รวมถึงนัดที่ไม่ได้รับมอบหมาย |
| สร้างนัด / ผู้สมัครผ่าน endpoint แยก | ได้ | ได้ | ไม่ได้ |
| แก้ไข / ยกเลิกนัด | ทุกนัด | ทุกนัด | เฉพาะนัดที่มีตนอยู่ในรายชื่อผู้รับมอบหมาย |
| เพิ่ม / เปลี่ยน / ล้างรายชื่อผู้รับมอบหมาย | ได้ | ได้ | ไม่ได้ แม้ตนได้รับมอบหมาย |
| ลบนัด | ทุกนัด | เฉพาะนัดที่ตนสร้าง | ไม่ได้ รวมถึงนัดที่ได้รับมอบหมาย |

- เพิ่มตาราง `meeting_interviewers(meeting_id, user_id, assigned_at)` เชื่อมแบบหลายต่อหลาย; คู่ meeting/user ไม่ซ้ำ
  และมี index `(user_id, meeting_id)` สำหรับตัวกรองนัดที่ได้รับมอบหมาย
- `createdById` / `isMine` ยังหมายถึงผู้สร้าง; รายชื่อ `interviewers` เป็นข้อมูลแยก ไม่โอนความเป็นผู้สร้างหรือสิทธิ์ลบ
- Recruiter/Admin เลือกผู้ใช้ที่ยืนยันบัญชีและมี role INTERVIEWER ได้ไม่เกิน 50 คนต่อนัด ค้นหาด้วยอีเมล
  บันทึกได้ทั้งตอนสร้างและแก้ไขนัด; ส่งรายการว่างเพื่อล้างการมอบหมาย
- ค้นหารายชื่อผ่าน `POST /interviewers/search` โดยส่ง `{query}` ใน JSON body เพื่อไม่ใส่อีเมลใน URL/access log
  เป็นการอ่านข้อมูลและไม่ใช้โควตาเขียนนัด; ยังตรวจ role และ same-origin ตามปกติ
- Interviewer แก้ไข field ของนัดที่ได้รับมอบหมาย รวมถึงผู้สมัครเดิม/ผู้สมัครใหม่ใน transaction เดียวกันได้
  แต่ส่ง `interviewerIds` ไม่ได้; การสร้างนัดและสร้างผู้สมัครผ่าน endpoint แยกยังเป็นสิทธิ์ Recruiter/Admin
- แก้รายชื่อผู้รับมอบหมายพร้อมข้อมูลนัดและผู้สมัครใน transaction เดียว ใช้ `version` ของนัดร่วมกัน
  เมื่อถอนมอบหมาย จะไม่มีสิทธิ์เขียนอีก แม้มีฟอร์มเก่าค้างอยู่; version เก่าต้องไม่เขียนทับรายชื่อใหม่
- ทุกการตรวจสิทธิ์อยู่ที่ API; UI แสดง Edit/Cancel เฉพาะผู้มีสิทธิ์ ไม่มี Delete สำหรับ Interviewer
  เปิดลิงก์นัดโดยตรงแล้วไม่มีสิทธิ์แก้ ให้แสดงรายละเอียดและ feedback แบบอ่านอย่างเดียว
- ตัวกรอง **ของฉัน** สำหรับ Recruiter/Admin ใช้ `mine=true` (ผู้สร้าง) ส่วน Interviewer แสดง **มอบหมายให้ฉัน**
  และใช้ `assignedToMe=true` ทั้ง List และ Calendar; **ทุกคน** ยังอ่านข้อมูลร่วมกันทั้งทีม
- นัดเดิมเริ่มไม่มีผู้รับมอบหมาย ไม่เดาจากผู้สร้างหรือคนที่เคยให้ feedback; Recruiter/Admin ต้องเลือกรายชื่อให้

## Alternatives

- ใช้ `created_by` เป็นเจ้าของ: ไม่ตรงกับผู้รับมอบหมายและทำให้ audit / สิทธิ์ลบเปลี่ยนความหมาย
- มีผู้สัมภาษณ์คนเดียวต่อนัด: ไม่รองรับ panel interview ตามที่ผู้ใช้เลือก
- ให้ Interviewer เปลี่ยนผู้รับมอบหมายหรือลบนัดได้: ผู้ใช้เลือกไม่อนุญาต

## Consequences

ต้อง migrate ฐานข้อมูลก่อน deploy API ที่ใช้ตารางใหม่ และ merge API ก่อน frontend ที่เพิ่มตัวเลือกมอบหมาย
การถอนมอบหมายไม่ลบ feedback เดิม และไม่ตัดสิทธิ์อ่านหรือเพิ่ม feedback; ยังไม่มีระบบแจ้งเตือนผู้รับมอบหมาย

## Revisit when

ต้องเชิญผู้สัมภาษณ์นอกระบบ มีหลายทีม/บริษัท หรือมีขั้นตอนตอบรับ/ปฏิเสธคำเชิญ
