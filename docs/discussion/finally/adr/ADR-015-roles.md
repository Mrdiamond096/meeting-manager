# ADR-015: Roles ADMIN / RECRUITER / INTERVIEWER

**Status:** Accepted (ผู้ใช้ตัดสิน 18 พ.ย. 2026) · แทนส่วน "ownership แบบทีม" ของ ADR-009 ที่ทุกคนทำได้ทุกอย่าง

## Context
ADR-009 ให้ผู้ใช้ทุกคนที่ login แล้วจัดการนัดได้ทั้งหมด เมื่อ deploy เป็น demo สาธารณะ ใครก็สมัครแล้วแก้หรือลบนัดของคนอื่นได้
และผู้สัมภาษณ์ที่ควรแค่อ่านและให้ผล ก็มีสิทธิ์เท่าผู้สรรหา

## Decision
| Action | ADMIN | RECRUITER | INTERVIEWER |
|---|---|---|---|
| ดูนัด ปฏิทิน ผู้สมัคร | ✅ | ✅ | ✅ |
| เพิ่ม feedback | ✅ | ✅ | ✅ |
| สร้าง / แก้ / ยกเลิกนัดใดก็ได้, สร้างผู้สมัคร | ✅ | ✅ (ทีมทำงานแทนกันได้) | 403 |
| ลบนัด | ทุกนัด | เฉพาะนัดที่ตัวเองสร้าง | 403 |

- สมัครสมาชิกเลือกได้แค่ **RECRUITER** (ค่าเริ่มต้น) หรือ **INTERVIEWER**; ส่ง `role: "ADMIN"` ได้ 400
- **ADMIN** มาจาก env `ADMIN_EMAILS` (อีเมลที่สมัครแล้วเป็น ADMIN) หรือจาก demo seed เท่านั้น
- ตรวจสิทธิ์ที่ API (`requireRole` บน route และเช็คเจ้าของใน service ตอนลบ); UI แค่ซ่อนปุ่มและอธิบายเมื่อเปิด URL ตรง
- Migration เปลี่ยนผู้ใช้เดิม `USER` เป็น `RECRUITER` เพื่อให้สิทธิ์เท่าเดิม; CHECK constraint บังคับ 3 ค่า
- Demo seed: `demo@example.com` เป็น ADMIN และเพิ่ม `interviewer@example.com` (รหัสผ่านเดียวกัน) เป็น INTERVIEWER

## Alternatives
- **Strict ownership** (แก้ได้เฉพาะนัดตัวเอง): ปฏิเสธ เพราะผู้สรรหาต้องเลื่อนหรือยกเลิกนัดแทนกันบ่อย
- **ปฏิทินส่วนตัว** (เห็นเฉพาะของตัวเอง): ปฏิเสธ ทีมต้องเห็นตารางรวมเพื่อกันนัดชน
- **ให้เลือก ADMIN ตอนสมัคร**: ปฏิเสธ เท่ากับไม่มีการแบ่งสิทธิ์

## Consequences
- การเลือก role ตอนสมัครยังเป็นการบอกเอง (self-declared): RECRUITER ยังสมัครเองได้ ควรเพิ่ม invite หรือ allowlist โดเมนอีเมล
  และหน้าให้ ADMIN เปลี่ยน role ก่อนใช้จริง
- ไม่มี audit log ว่าใครแก้หรือลบ; `created_by` บันทึกแค่ผู้สร้าง

## Revisit when
มีหลายทีมหรือหลายบริษัท (ต้อง scope ตามทีม), หรือต้องการให้ interviewer เห็นเฉพาะนัดที่ตัวเองถูกเชิญ
